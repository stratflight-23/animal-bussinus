# Gorilla Company — Unity VR game

A VR game in the style of Animal Company / Gorilla Tag, built by a dad (Oscar) and his son.
Long-term goal: players build things using "Goop" (not built yet).
Both are beginners, so explain things simply and give exact click-by-click steps for anything done in the Unity editor.

## Machines
- Son's laptop: ThinkPad, **Omarchy (Arch Linux, Hyprland)**. This project lives at `~/animal bussinus`.
  - Use `omarchy update` for system updates, never plain `sudo pacman -Syu` (Omarchy blocks it).
  - Installed: Unity Hub (AUR `unityhub`), VS Code (`visual-studio-code-bin`), `dotnet-sdk` 10, VS Code Unity extension.
  - Known AUR update failures (hermes-agent needs uv>=0.13.5, python311 needs openssl-3): not related to this project, ignore.

## Our scripts
- `Assets/Scripts/gorillalocomotion.cs` — player movement on the Rigidbody player root. Left stick walks (relative to head yaw),
  right A button jumps, either grip grabs walls (only while airborne), max 10s climb that only refills on the ground,
  release grip / press A = wall-jump fling, timer runout = slide off. Input read in Update, physics in FixedUpdate,
  ground/wall contacts reset each physics step. Uses legacy `UnityEngine.XR.InputDevices` (works with OpenXR).
- `Assets/Scripts/PlayerDeathPhysics.cs` — `TriggerDeath(Vector3 dir)`: disables movement, knockback launch, optional tumble
  (OFF by default — spinning the camera in VR causes motion sickness), auto-respawn after 3s at a respawn point or start position.
- `Assets/Scripts/KillZone.cs` — trigger collider that calls TriggerDeath on the player.
- `Assets/Scripts/FloorTracking.cs` — sets XR tracking origin to Floor so the head is at real standing height.
- `Assets/Editor/GorillaCompanySetup.cs` — adds a **Gorilla Company** menu:
  1. *Install VR Packages*: adds `com.unity.xr.management` + `com.unity.xr.openxr` via Package Manager client.
  2. *Build VR Test Scene*: creates `Assets/Scenes/GorillaTest.unity` (floor, climb walls, tower, lava kill zone,
     GorillaPlayer with Rigidbody + capsule + no-friction material + all scripts, camera and hand spheres driven by
     Input System `TrackedPoseDriver`), and makes it the first enabled scene in Build Settings.
  These were written without being compiled — first job is to check the Unity Console for compile errors and fix them.

- `Assets/Editor/BuildGame.cs` — **Gorilla Company > Build** menu: *Quest (Android APK)* → `Builds/Quest/GorillaCompany.apk`
  (forces IL2CPP + ARM64), *Linux Desktop* → `Builds/Linux/GorillaCompany.x86_64`. Uses the scenes ticked in Build Settings.
  Command-line entry points: `BuildGame.BuildQuest`, `BuildGame.BuildLinux`.

## Weapons, grabbing and the Goop Copter (added Nov 20, 2026)
All looks are ORIGINAL, built only from Unity primitives (cube/sphere/capsule/cylinder) colored with `PrimitiveColor`
(a MaterialPropertyBlock, so no material files). Sounds are generated by code (`SoundFx`), no audio files.
- **Grab system** (`Assets/Scripts/Grab/`): `HandGrabber` on each hand (auto-added at play by `GorillaRigBootstrap`, which
  also adds `Health` + `StatusEffects` to GorillaPlayer). Grip near a `Grabbable` = pick up (item rides on "Camera Offset"
  because the hand spheres are scaled 0.1), release = throw with hand velocity, trigger = use. `GripHandle` = grabbable
  thing that doesn't come off (copter levers). `gorillalocomotion` ignores grip on a hand that is holding/touching an
  item or handle (`HandGrabber.IsBusy`), and has `speedMultiplier` (set by StatusEffects).
- **Combat** (`Assets/Scripts/Combat/`): `Health` (HP, shield, events; on the player it calls PlayerDeathPhysics),
  `StatusEffects` (slow/freeze/burn/stun/speed + tints), `EffectSystem` (all 12 effects in one place), `Combat`
  (HitTarget / HitArea / Impact), `TrainingDummy` (damage numbers, wobble, KO + respawn; `TrainingDummy.Create`).
- **Weapons** (`Assets/Scripts/Weapons/`): `WeaponData` ScriptableObject (stats + shape recipe), one `Weapon` component
  for every attack type, `Projectile`, `WeaponRackSlot` (refills 3 s after a weapon is taken).
  The 100 weapons are defined in `Assets/Editor/WeaponCatalog.cs` (10 categories x 10). Generated files:
  `Assets/Weapons/Data/*.asset` and `Assets/Weapons/Prefabs/*.prefab`. To rebalance, edit the catalog and re-run menu 4
  (re-running overwrites hand edits made to the .asset files).
- **Goop Copter** (`Assets/Scripts/Copter/GoopCopter.cs`, builder in `Assets/Editor/GoopCopterSetup.cs`): seat is a child
  of the root (yaw only) and the tilting "Body" is separate, so the VR view never rolls/pitches. Fuel drains in the air,
  refills on the ground; out of fuel = soft fall (max 3.5 m/s).

## Building from the command line
Unity must be **closed** for batch-mode builds. Editor lives under `~/Unity/Hub/Editor/6000.6.10f1/Editor/Unity`.
Use `-batchmode -quit -projectPath "$HOME/animal bussinus" -executeMethod <BuildScript.Method> -logFile -` with a build
script in `Assets/Editor/`. Builds can take a long time; run them in the background and watch the log.

## For Dad (Windows)
**One-time setup**
1. Install **GitHub Desktop**: https://desktop.github.com → run the installer → sign in with your GitHub account.
   (The son must first invite you: on GitHub, repo `gorilla-company` > Settings > Collaborators > Add people.)
2. Install **Git LFS**: https://git-lfs.com → download → run the installer. Then open "Command Prompt" and run `git lfs install` once.
   (GitHub Desktop also handles LFS on its own, but this makes sure it's on.)
3. Clone: GitHub Desktop > File > Clone repository > pick `gorilla-company` > choose a folder (e.g. `Documents\GitHub\gorilla-company`) > Clone.
   The first clone downloads ~250 MB of art/sound/video, so it can take a few minutes.
4. Install the **exact same Unity version**: Unity Hub > Installs > Install Editor > Archive tab > find **6000.6.10f1**.
   Tick **Android Build Support** (with OpenJDK and Android SDK & NDK Tools) so you can build for Quest too.
5. Open: Unity Hub > Projects > **Add** (dropdown) > **Add project from disk** > pick the cloned folder.
   Make sure the version shown next to it is 6000.6.10f1. If Hub offers to upgrade it, say **no**.
   The first open takes a while because Unity rebuilds the `Library` folder (that folder is never shared).

**The routine (both of us, every time)**
1. **Pull before you start** — GitHub Desktop > Fetch origin > Pull. Do this with Unity *closed*.
2. Work in Unity. Save the scene (Ctrl+S).
3. **Commit and push when you stop** — GitHub Desktop: type a short summary of what you did > Commit to main > Push origin.
4. **Don't both edit the same scene at the same time.** Scene files can't be merged nicely. Say "I'm working in GorillaTest" first
   (text each other). Scripts and different scenes are fine to work on at the same time.
5. If GitHub Desktop says there's a conflict and you're not sure, stop and ask — don't click "use mine" on a scene.
